# tool-evaluation

## Process

1. define required outcome and current baseline
2. inventory existing assets and simpler alternatives
3. test capability, integration friction, security/data boundaries and failure modes
4. estimate operating/lock-in/migration cost
5. run a reversible pilot when uncertainty is material
6. recommend adopt/reject/defer with evidence

## Constraints

- feature lists are not evaluations
- do not adopt infrastructure because it is fashionable

## Output

Produce the smallest durable artifact/evidence needed by the active work item. Separate facts, assumptions, findings, risks, and unresolved gates.
