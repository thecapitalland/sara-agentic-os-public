# Operating Model

## Objective

Move from intent to accepted outcome while minimizing human relay, rework, context waste, unnecessary invocation, coordination overhead, and authority ambiguity.

## 1. Discovery
Test the premise. Define the real problem, measurable outcome, non-goals, constraints, assumptions, alternatives, risks, and kill conditions.

## 2. Authorize material work
Use a durable Work Item that defines scope, allowed/forbidden writes, risk, capabilities, acceptance criteria, evidence, gates, recovery, and stop conditions.

## 3. Compose context
Load only the minimum useful evidence: system invariants, objective/work item, current State/Gates, relevant decisions, task-relevant repository evidence, selected Skills, and external evidence only when necessary.

## 4. Route capability
Default to direct execution. Invoke a specialist only when independent context or judgment materially improves the task.

## 5. Execute bounded change
Every material lane has an objective, write scope, forbidden scope, validation, output contract, and stop conditions. Scope expansion creates a new decision boundary.

## 6. Verify
Prefer deterministic evidence before confidence. Add independent review for material or protected work.

## 7. Human gates
Explicit human authorization is required for protected actions defined in the manifest.

## 8. Result and reconciliation
Record candidate identity, changed surfaces, validation, acceptance, reviews, residual risks, omissions, and next gate. Completion requires applicable State, Gates, Result, candidate, and human acceptance to agree.

Statuses: READY, ACTIVE, BLOCKED, REVIEW, UAT, RELEASE, DONE.
